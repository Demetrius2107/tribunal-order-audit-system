# 压测验证指南（M6：真实负载验证）

> **定位**：对已实现的关键能力做简单压测验证——超时关单闭环、并发超卖防护、网关限流。
> **前置**：`docker compose up -d` 起中间件（MySQL/Nacos/Redis/Kafka），各服务启动后执行。
> **工具**：`curl` + bash 脚本（见同目录 `压测.sh`），无需额外压测工具。

---

## 场景一：超时关单闭环（task-service 定时调度）

**目标**：验证超时未确认订单被自动关闭，TaskLog 留痕。

| 步骤 | 命令 | 预期 |
|------|------|------|
| 1. 批量下单（不审单） | 见 `压测.sh`：循环 POST `/api/orders` × N 单 | 全部 TO_BE_CONFIRMED |
| 2. 触发关单 | 手动调 `POST /api/orders/timeout-close?minutes=30`（模拟 task-service 调度） | 返回 closedCount=N |
| 3. 查订单状态 | `GET /api/orders?status=CANCELLED` | 超时单全部 CANCELLED |
| 4. 查 TaskLog | task-service `t_task_log` 表 | TIMEOUT_CLOSE_ORDER processedCount=N |

**注意**：timeout-close 的 `minutes` 参数是"创建时间早于 now-minutes"，压测可用小值（如 0/1）立即关闭。

---

## 场景二：并发超卖防护（inventory 乐观锁）

**目标**：验证并发预占不超卖（乐观锁 + 重试）。

| 步骤 | 命令 | 预期 |
|------|------|------|
| 1. 建库存 | `POST /api/inventory/items`（total=100） | 总库存 100 |
| 2. 并发预占 | `压测.sh`：20 线程 × 每线程 reserve 6（需求 120 > 100） | 成功数 × 6 ≤ 100 |
| 3. 查库存 | `GET /api/inventory/items/SKU` | reserved ≤ 100（不超卖） |
| 4. 查流水 | `GET /api/inventory/flows?changeType=RESERVE` | 流水条数 = 成功数 |

**预期结果**：约 16~17 个线程成功（16×6=96 ≤ 100），失败线程抛 400001/400002，**最终 reserved 恒 ≤ 100**。

---

## 场景三：网关限流（Gateway RequestRateLimiter）

**目标**：验证网关 50/s 令牌桶限流生效。

| 步骤 | 命令 | 预期 |
|------|------|------|
| 1. 登录拿 Token | `POST /api/auth/login` | 拿到 accessToken |
| 2. 突刺请求 | `压测.sh`：单线程快速打 `GET /api/orders` × 200 次 | 前 ~100 次 200，超限后 **429** |
| 3. 查响应 | 统计 HTTP 状态码分布 | 429 占比 ≈ (200-100)/200 |

**预期结果**：burstCapacity=100 允许突发 100 个，之后按 50/s 补充，超出即 429。

## 附录：压测脚本用法

```bash
bash docs/验证/压测.sh --scene order-timeout   # 场景一
bash docs/验证/压测.sh --scene over-sell       # 场景二
bash docs/验证/压测.sh --scene rate-limit      # 场景三
```

各场景均输出状态码/计数统计，供对照上表预期。
