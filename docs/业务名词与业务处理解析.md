# 业务名词与业务处理解析（订单审单系统）

> 领域：B2B 订单管理（经销商渠道订货，对接下游处理系统）
> 定位：本文档是业务术语词典 + 业务处理规则说明，作为学习与开发的业务参照
> 覆盖：订单状态、促销、折扣、押金、整托、信用、预购、拼车、价格、渠道等

---

## 一、订单状态机（核心）

订单在生命周期中经历多个状态，状态码由业务系统定义，业务系统侧用语义常量管理：

| 状态码 | 常量 | 语义 | 说明 |
|---|---|---|---|
| - | TO_BE_CONFIRMED | 待确认 | 下单初始状态，等待审单 |
| 101 | ORDER_RELEASE | 已释放（审核中） | 订单审核通过、信用检查通过 |
| 103 | ORDER_SHIPMENT | 已发货（待签收） | 发货完成 |
| 104 | ORDER_SIGN | 已签收（已完成） | 终态之一 |
| 105 | PART_SHIPMENT | 部分发货 | 允许前置状态之一 |
| 106 | ORDER_EXCHANGE | 已换货 | 售后场景 |
| 107 | ORDER_RETURN | 已退货 | 售后场景 |
| 108 | DELIVERY_END | 发货终止 | |
| 201 | ORDER_CLOSED | 已关闭 | 发货前取消 |
| 202 | ORDER_DELETED | 已删除 | |
| 203 | ORDER_AGAIN_OPEN | 重新打开 | |
| 303 | ORDER_RECEIVED_PAYMENT | 已收款 | 财务确认收款 |
| 998 | ORDER_STOP | 预购已结束 | 预购单专用终态 |
| 999 | ORDER_TRANSFERRED | 已转销售订单 | 已转移至下游 |

**关键业务规则**：
- 状态迁移必须符合预定义状态流（前置状态校验），非法迁移拒绝
- **重复状态回传**（如已 103 再收到 103）→ 拒绝（幂等）；部分状态允许重复触发（如 101/105 前置、005/301 前置）
- 每个状态变更记录状态流水（order_status_process_record），可审计、可追溯

## 二、促销（营销域）

促销是吸引经销商的订单激励，按适用对象分两类：

| 类型码 | 常量 | 定义 |
|---|---|---|
| 1 | PROMOTION_TYPE_CUSTOMER | 客户型促销：针对单个经销商 |
| 2 | PROMOTION_TYPE_GROUP | 客户组型促销：针对一组经销商 |

**业务处理**：
- 促销是否参与订单：`PROMOTION_TYPE_IS=1`（是促销订单）/ 非 1（普通订单）
- 促销与 SKU 组挂钩（sales_promotion_sku_group），即促销只作用于组内 SKU
- 促销计算引擎按购物车行逐行计算折扣金额，支持普通单与预购单两套口径
- 促销政策组数校验（部分区域 BU 特有规则：下单前校验促销政策组是否够用）

## 三、折扣（价格域）

| 名词 | 定义 | 业务处理 |
|---|---|---|
| 折扣率 | 按客户组/SKU 组配置的折扣百分比 | 审单/下单时按行计算 |
| 折扣池 | 经销商账户中的折扣余额（促销返还） | 下单时可抵扣信用/应付金额 |
| 折扣池抵扣信用 | 用折扣池余额冲抵信用占用 | 经销商 100% 抵扣或 40% 抵扣（按客户配置） |
| 折扣类型 | 1=不应用折扣 / 2=自动应用折扣 | 控制折扣是否自动生效 |
| 最高折扣 | 单笔订单允许的最大折扣额度 | 防超折扣 |
| 最大折扣 | 客户允许的最大折扣率 | 信用/价格双重约束 |

**业务处理（应付款计算）**：总金额 → 扣折扣 → 扣折扣池抵扣 → 扣信用占用 → 得应付金额。折扣池余额不足时按最小值抵扣。

---

## 四、押金（计费项）

押金是按包装物类型的计费项，类型可由主数据配置（如各类包装容器、托盘、垫板等），系统按类型管理：

| 类型码 | 常量 | 定义 |
|---|---|---|
| 1 | DEPOSIT_TYPE_1 | 包装押金类型 1 |
| 2 | DEPOSIT_TYPE_2 | 包装押金类型 2 |
| 3 | DEPOSIT_TYPE_3 | 包装押金类型 3 |
| 4 | PALLET_DEPOSIT | 托盘押金 |
| 5 | DEPOSIT_TYPE_5 | 包装押金类型 5（垫板/顶板类） |

**业务处理**：
- 押金是否计入价格：可配置（计入/不计入）
- 购物车行按 SKU 查找客户-SKU 押金配置（customer_sku_deposit），计算押金金额
- 押金与折扣、税并列参与订单金额汇总

## 五、整托（行业特有校验）

| 名词 | 定义 |
|---|---|
| 整托 | 按托盘为单位的售卖方式，SKU 数量必须是整托规格的倍数 |
| 整托规格 | 每托多少件/箱（sku_pallet 表，外部同步） |
| 免整托产品 | 不参与整托校验的产品（is_pallet_type = DO_NOT_CHECK_TRAY_PRODUCTS） |

**业务处理（wholePalletCheck）**：
- 下单/审单时校验：SKU 数量 % 整托规格 == 0，否则拒绝
- 优先取整托规格表数据；部分区域有本地整托信息
- 整托信息参与运费、车型（最大托盘数）计算

## 六、信用（财务域）

| 名词 | 定义 |
|---|---|
| 信用组 | 按客户信用等级分组的配置（credit_group） |
| 信用组配置 | 组内信用额度、折扣池抵扣比例等（credit_group_configuration） |
| 信用检查 | 下单/审单时校验客户可用信用 ≥ 应付金额 |
| 信用占用/释放 | 下单冻结信用，取消/签收释放 |

**业务处理（creditProcessing）**：
- 下单：占用信用（预占），更新客户余额明细（customer_balance_detail）
- 审单：正式扣减信用
- 信用不足 → 拒绝下单/审单，返回错误码
- 预购单走独立信用口径（预购应付金额、保证金余额）

---

## 七、预购（预付款业务）

| 名词 | 定义 |
|---|---|
| 预购 | 提前采购下单，经销商预付/保证金模式 |
| 预购活动 | 预购活动主档（pre_order_activity） |
| 预购客户组/SKU组 | 参与预购的客户与 SKU 范围 |
| 预购订单记录 | 预购订单明细（pre_order_record） |

**业务处理**：
- 预购单类型标识（PRE_ORDER_TYPE），状态机有独立终态 998（预购已结束）
- 预购应付款：补缴 + 保证金余额计算（部分 BU 特有）
- 预购促销/折扣池有独立计算口径（totalCalculatePreOrderDiscount / calculateDiscountPoolAmountPreOrder）
- 订单关闭时删除预购占用记录

---

## 八、拼车（物流业务）

| 名词 | 定义 |
|---|---|
| 拼车 | 多个经销商订单合并为一车运输 |
| 拼车组 | 拼车分组配置（car_sharing_group） |
| 拼车状态 | CAR_SHARING（拼车）/ 非拼车 |

**业务处理**：
- 订单可标记是否拼车（whether_the_car_pool）
- 关闭拼车时校验：该订单是否已参与拼车（已拼车则不可关闭，CARPOOL_CANNOT_BE_CLOSED）
- 转单时拼车订单走独立转单逻辑（carpoolTransfer）

---

## 九、空包装回收（包装物退回）

| 名词 | 定义 |
|---|---|
| 空包装回收 | 经销商退回空包装物，订单可包含回收明细（returnable_packaging） |
| 含包装/不含包装销售 | 销售方式标识：含包装出售（商品+包装）或不含包装 |

**业务处理**：下单时提交空包装回收明细，订单保存时写入回收表；回收参与订单金额/押金计算。

## 十、价格体系

| 名词 | 定义 |
|---|---|
| 价格组 | 客户/SKU 分组价格（price_group） |
| 销售价 | 客户实际成交价（sales_price / price） |
| 运费 | 按 SKU + 地址运费关系计算（address_freight_relation） |
| 渠道价 | 渠道映射（CHANNEL_MAPPING：特定渠道等） |

**业务处理**：价格选择按"客户 → 客户组 → 区域"优先级取价；运费按送货地 + SKU 计算。

## 十一、组织与权限名词

| 名词 | 定义 |
|---|---|
| 经销商 | 下单主体（customer），有信用额度、价格组、促销组 |
| 销售（销售账号） | 经销商归属的销售员（sales_representative / customer_sales_relation），两级审批链 |
| BU | 业务单元（按区域划分），不同 BU 有不同的业务规则（渠道必填、促销组校验、订单修改时限） |
| 区域 | 经销商所属销售区域，影响订单修改规则 |
| 渠道 | 销售渠道，渠道映射到下游渠道编码 |

**业务处理**：
- 审批链：经销商下单 → 销售一级/二级审批 → 邮件/微信通知
- 订单修改规则按区域差异化：如部分区域在运输计划确认前可改，其他区域在 下游释放前可改

## 十二、业务处理全景（一图梳理）

```
下单（经销商）
  │
  ├─ 校验：促销组数（部分区域） / 渠道必填（部分 BU） / 整托校验 / 信用占用
  ▼
订单创建（待确认）── 状态流水记录
  │
  ├─ 审单（销售）→ 确认 / 拒绝
  │     ├─ 信用校验（可用信用 ≥ 应付）
  │     └─ 金额计算（总金额-折扣-折扣池抵扣-押金-税=应付）
  ▼
转单生成账单（billing-service）── 状态：转单中 → 已转单
  │
  ├─ 账单/履约回传状态：发货 103 / 签收 104 / 部分发货 105 / 关闭 201 / 取消
  ▼
终态：签收完成 / 关闭 / 取消 / 预购结束
```

## 十三、库存物料域（上游物料推送）

> 行业实践：生产级库存体系通常分层建设（中央库存三层模型：销售层 / 调度层 / 仓库层），
> 本系统骨架以单个库存物料模块承载，演进时可按此拆分。

| 名词 | 定义 |
|---|---|
| 物料主数据 | SKU 基础信息（编码/名称/单位），库存域的数据基础，向上游推送 |
| 实物库存 | 仓库实际库存（在途/可用/不可用），由入库/出库流水驱动 |
| 可用库存 | 可售量 = 实物库存 - 预占库存（销售可用） |
| 预占库存 | 下单时锁定、取消/发货时释放的库存量（防超卖核心） |
| 库存调度 | 多仓/多库位间的库存汇总与分配（调度层），本骨架未涉及 |
| 渠道库存同步 | 库存量同步到各销售渠道（自营直读 / 三方平台推送） |
| 库存变动流水 | 每次预占/释放/入库/出库的记录（审计 + 对账依据） |

**业务处理**：
- 下单/审单时：查询可售量 → 校验足量 → 预占库存（逐 SKU）
- 取消/签收时：释放预占
- 物料/库存变化：向上游推送（F-501 数据来源），流水同步需幂等（防重复同步导致库存错账）
- 骨架实现：`tribunal-inventory-service`（物料 + 库存账 + 预占/释放接口）
- 演进拆分：实物库存中心 / 库存调度中心 / 渠道库存同步（对应中央库存三层）

## 十四、财务审核域（下游金融计算）

> 行业实践：生产级结算平台按 DDD 划分清分 / 清算 / 结算 / 对账四大域，
> 本系统骨架以单个金融账单模块承载订单财务审核，演进时可按此拆分。

| 名词 | 定义 |
|---|---|
| 账单 | 订单转来后生成的财务单据（含明细与金额），是财务审核的载体 |
| 清分 | 对交易明细的核对、识别、调整、打标（数据标准化预处理） |
| 清算 | 标准化数据的计算与核对（计费、分摊、累额） |
| 结算 | 汇总账单并完成资金转移（生成结算单、确认、推送财务渠道收付款） |
| 对账 | 交易数据与渠道/银行数据核对（发现差异即差错/在途数据） |
| 收款流水 | 结算时的收款明细记录（审计 + 对账依据） |
| 核销 | 账务核销完成（应收应付抵消），账单终态之一 |
| 差错处理 | 对账发现的未对平数据（单边数据）的人工/自动处理 |

**业务处理**：
- 审单通过 → 订单转来 → 生成账单（初始：已生成）
- 财务审核：账单确认（已确认）→ 收款/结算（已结算）→ 账务核销（已核销）→ 回传订单驱动状态机
- 订单取消 → 账单取消（终态）
- 骨架实现：`tribunal-billing-service`（账单 + 账单状态机 + 回传）
- 演进拆分：清分中心 / 清算中心 / 结算中心 / 对账中心（对应结算平台四大域）
