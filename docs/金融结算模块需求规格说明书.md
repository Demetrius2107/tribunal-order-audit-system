# 金融结算模块需求规格说明书（PRD）

> 版本：v1.0  
> 编写日期：2026-08-03  
> 适用范围：订单履约后的账单计算、支付扣款、分账、退款、结算全链路

---

## 1. 概述

### 1.1 背景
订单审单通过后，进入履约阶段，需完成资金层面的处理：账单生成、费用计算、支付扣款、多方分账、结算打款、退款冲正。本模块承担"资金结算中枢"职责，确保每一笔订单的资金流**准确、安全、可追溯、可审计**。

### 1.2 目标
- 实现订单到资金的**端到端闭环**，支持正向（收款）与逆向（退款）全流程
- 建立**幂等扣款机制**，杜绝重复扣款等资损风险
- 支持**复杂分账场景**（平台、商家、物流、分销商多方分润）
- 提供完整的**对账能力**，与支付渠道、内部财务系统日终对账
- 满足**合规与风控**要求，拦截异常交易

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 结算单 | 以订单/批次为维度生成的资金结算凭证，是财务核算的最小单元 |
| 分账 | 将一笔订单的实收金额按规则拆分给多个收款方 |
| 佣金 | 平台从商家销售额中抽取的服务费比例 |
| 支付渠道 | 微信支付、支付宝、银联、Apple Pay 等第三方支付机构 |
| 预授权 | 先冻结用户资金，履约完成后再正式扣款（常见于酒店/预付费场景） |
| 轧差 | 每日对账时，将应收应付相互抵消，只结算净额 |
| 资损 | 因系统Bug、重复扣款、数据错误导致的资金损失 |
| T+N | 交易发生后第 N 个工作日进行结算打款 |

## 2. 功能需求

### 2.1 账单生成层

#### 2.1.1 订单事件监听
- **FR-001**：监听订单状态变更事件（`OrderApproved`、`OrderShipped`、`OrderCompleted`、`OrderCancelled`）
- **FR-002**：支持消息队列（Kafka/Service Bus）消费模式，与订单系统解耦
- **FR-003**：支持补偿机制：漏消费事件时，可通过订单号主动补生成账单

#### 2.1.2 账单明细拆解
- **FR-004**：每笔订单必须生成结构化账单，至少包含以下明细项：
  - 商品金额（SKU × 单价 × 数量）
  - 运费（按重量/距离/区域计算）
  - 优惠分摊（优惠券、满减、积分抵扣按比例分摊到每个 SKU）
  - 平台服务费/佣金（按品类费率 × 商品金额）
  - 支付手续费（按支付渠道费率 × 实付金额）
  - 税费（增值税/消费税，按税法规则计算）
  - 包装费、保价费、其他附加费（可配置）
- **FR-005**：优惠分摊必须精确到分，各 SKU 分摊金额之和 = 总优惠金额（误差 ≤ 1 分由最后一个 SKU 吸收）
- **FR-006**：运费计算支持多模板：按重量阶梯、按距离、按区域固定价、包邮阈值

#### 2.1.3 多币种支持
- **FR-007**：支持人民币（CNY）、美元（USD）、欧元（EUR）、港币（HKD）等主流币种
- **FR-008**：跨境订单支持实时汇率转换，账单同时记录原币金额和本位币金额
- **FR-009**：汇率来源可配置：央行中间价、第三方支付渠道汇率、自定义汇率表
- **FR-010**：汇率波动超过阈值（如 2%）时触发人工审核

### 2.2 支付扣款层

#### 2.2.1 支付编排
- **FR-011**：支持组合支付：余额 + 信用卡 + 优惠券 + 积分（可配置优先级和组合规则）
- **FR-012**：支持预授权模式：先冻结资金，履约完成后再扣款（适用于酒店/定制商品）
- **FR-013**：支持分期支付：与花呗/白条/信用卡分期对接，账单记录每期应还金额
- **FR-014**：支持账期支付：企业用户可先下单后付款，生成应收账款

#### 2.2.2 幂等扣款
- **FR-015**：核心红线：同一结算单号绝对不能重复扣款
- **FR-016**：幂等机制：扣款前查询"该结算单是否已扣款成功"，已扣款直接返回成功
- **FR-017**：幂等键：结算单号 + 扣款批次号（每次重试生成新批次号，但结算单号不变）
- **FR-018**：支付渠道返回超时：标记为"处理中"，定时任务轮询渠道状态，禁止立即重试
- **FR-019**：支付渠道返回失败：记录失败原因，允许人工重试或自动重试（限 3 次）

#### 2.2.3 扣款状态管理
- **FR-020**：扣款状态机：
  ```
  待扣款 → 扣款中 → [扣款成功 → 待分账 → 已分账 → 已结算]
                     [扣款失败 → 待重试 → 扣款中]
                     [扣款超时 → 处理中 → 扣款成功/扣款失败]
  ```
- **FR-021**：状态流转必须记录流水日志，禁止跳过状态（如不能从"待扣款"直接到"已分账"）
- **FR-022**：扣款成功必须收到支付渠道的明确成功回执（不能仅靠 HTTP 200 判断）

### 2.3 分账层

#### 2.3.1 分账规则引擎
- **FR-023**：支持动态分账规则配置，可按品类、商家等级、活动期、区域配置不同费率
- **FR-024**：分账方至少支持：平台、商家、物流服务商、分销商、推广员
- **FR-025**：分账比例校验：所有分账方比例之和 = 100%（误差由平台方吸收）
- **FR-026**：支持阶梯分账：销售额 < 1万抽 5%，1-10万抽 3%，>10万抽 2%
- **FR-027**：支持固定金额分账：物流费固定 10 元归物流公司，剩余按比例分

#### 2.3.2 分账执行
- **FR-028**：支持实时分账：扣款成功后立即按规则拆分资金到各分账方账户
- **FR-029**：支持延迟分账：T+1 / T+7 / 月结，按配置定时触发分账任务
- **FR-030**：分账失败处理：某分账方账户异常时，资金暂存到"待分账冻结账户"，人工处理
- **FR-031**：分账回退：订单退款时，已分账资金必须按原路回退（从各分账方账户扣回）

#### 2.3.3 分账账户管理
- **FR-032**：每个分账方（商家/物流）拥有独立虚拟账户，记录：可用余额、冻结余额、在途金额
- **FR-033**：支持账户提现：分账方发起提现申请，审核通过后打款到绑定银行卡
- **FR-034**：提现手续费自动扣除，支持按笔收费或按金额比例收费
- **FR-035**：账户余额不足时，禁止继续分账，触发告警通知运营

### 2.4 退款/冲正层

#### 2.4.1 退款触发场景
- **FR-036**：用户取消订单（未发货）：全额退款
- **FR-037**：用户退货（已发货）：退商品金额，不退运费（或按策略退部分运费）
- **FR-038**：部分退货：只退退货 SKU 的金额（含其分摊的优惠）
- **FR-039**：订单差价补偿：商品降价后，给用户退差价
- **FR-040**：系统错误补偿：重复扣款、多扣金额等异常，发起人工退款

#### 2.4.2 退款计算
- **FR-041**：退款金额必须精确到分，重新计算该 SKU 的分摊优惠、税费、佣金
- **FR-042**：退款后佣金回退：平台已抽的佣金按比例退回商家
- **FR-043**：退款后分账回退：从各分账方账户扣回已分资金，不足部分记为"待扣回欠款"
- **FR-044**：退款路径：原路退回（微信付的退微信，余额付的退余额）

#### 2.4.3 退款状态管理
- **FR-045**：退款状态机：
  ```
  待审核 → 审核通过 → 退款中 → [退款成功 → 已退款]
                          [退款失败 → 待重试 → 退款中]
  ```
- **FR-046**：大额退款（> 5000 元）必须人工审核
- **FR-047**：退款时效承诺：24 小时内完成，超时自动升级告警

### 2.5 结算与打款层

#### 2.5.1 结算周期管理
- **FR-048**：支持多种结算周期：实时结算、T+1、T+7、月结（每月 1 日/15 日）
- **FR-049**：结算周期按商家/品类可配置，支持活动期间临时调整
- **FR-050**：结算批次管理：同一结算周期的订单汇总为一个结算批次，生成结算单

#### 2.5.2 结算单生成
- **FR-051**：结算单包含：批次号、商家信息、订单明细、应收金额、应付金额、平台佣金、手续费
- **FR-052**：支持轧差结算：商家应收和应付相互抵消，只结算净额（减少转账次数）
- **FR-053**：结算单生成后锁定对应订单资金，禁止再次分账或退款

#### 2.5.3 打款执行
- **FR-054**：支持银行转账、支付宝转账、微信企业付款等多种打款渠道
- **FR-055**：打款前校验：收款账户信息、账户状态、单笔限额、日累计限额
- **FR-056**：打款失败处理：账户信息错误 → 通知商家更新；银行系统故障 → 定时重试
- **FR-057**：打款成功必须收到银行/渠道的明确回执，更新结算单状态为"已结算"

### 2.6 对账层

#### 2.6.1 支付渠道对账
- **FR-058**：每日自动与支付渠道对账：
  - 我方记录：订单号、结算单号、扣款金额、扣款时间、支付渠道流水号
  - 渠道流水：渠道流水号、金额、时间、状态
  - 匹配规则：按"支付渠道流水号 + 金额"匹配，差异 > 0 记为异常
- **FR-059**：对账差异类型：
  - 单边账：我方有、渠道无（或反之）
  - 金额差异：双方金额不一致（可能手续费计算差异）
  - 状态差异：我方成功、渠道失败（或反之）
- **FR-060**：差异自动处理：手续费差异在阈值内（如 0.01 元）自动平账，超出阈值进人工审核

#### 2.6.2 内部系统对账
- **FR-061**：与订单系统对账：订单状态为"已完成"的订单，必须有对应的结算单
- **FR-062**：与库存系统对账：已扣款的订单，必须有对应的出库记录（防止空转）
- **FR-063**：与财务系统对账：每日汇总应收应付数据推送财务系统，差异告警

#### 2.6.3 对账报告
- **FR-064**：自动生成日终对账报告：总笔数、成功笔数、差异笔数、差异金额
- **FR-065**：对账报告支持导出 Excel/PDF，供财务审计
- **FR-066**：差异订单支持一键标记"已处理"或"发起退款/补扣"

### 2.7 风控与合规层

#### 2.7.1 交易风控
- **FR-067**：实时风控规则：
  - 单笔金额 > 阈值（如 10 万元）触发人工审核
  - 同一用户 1 小时内连续下单 > 10 笔且金额异常，触发反欺诈
  - 新用户首单金额 > 阈值，触发身份验证
  - 同一银行卡短时间内被多用户绑定，触发盗刷预警
- **FR-068**：风控拦截后，订单进入"风控审核中"状态，审核通过后才允许扣款

#### 2.7.2 资金合规
- **FR-069**：敏感操作必须记录审计日志：扣款、退款、分账、提现、修改费率
- **FR-070**：审计日志不可篡改，保留期限 ≥ 5 年（满足监管要求）
- **FR-071**：用户敏感信息（银行卡号、身份证号）加密存储（AES-256），展示时脱敏
- **FR-072**：符合 PCI-DSS 支付卡行业安全标准（如适用）
- **FR-073**：税务合规：自动计算增值税/消费税，生成税务申报所需数据

### 2.8 发票管理

#### 2.8.1 发票申请
- **FR-074**：用户可在订单完成后申请开具电子发票
- **FR-075**：支持发票类型：增值税普通发票（电子）、增值税专用发票（纸质/电子）
- **FR-076**：发票内容按 SKU 品类自动匹配税收分类编码

#### 2.8.2 发票处理
- **FR-077**：发票金额 = 实付金额 - 退款金额（部分退款后发票金额相应减少）
- **FR-078**：退货后自动发起红冲发票（负数发票），原发票作废
- **FR-079**：发票状态管理：待开票 → 开票中 → 已开票 → 已推送（邮箱/短信）
- **FR-080**：支持发票批量开具和推送，支持对接税控系统（百旺/航信）

## 3. 非功能需求

### 3.1 性能
- **NFR-001**：账单生成延迟 < 200ms（从接收订单事件到生成账单）
- **NFR-002**：单笔扣款接口响应时间 < 3s（含支付渠道交互）
- **NFR-003**：日终对账任务处理 10 万笔数据 < 30 分钟
- **NFR-004**：分账计算支持 10 个分账方，计算时间 < 100ms

### 3.2 可用性
- **NFR-005**：扣款核心链路可用性 SLA > 99.99%（全年停机 < 52 分钟）
- **NFR-006**：支付渠道超时或故障时，支持降级：标记为"处理中"，不阻塞用户流程
- **NFR-007**：对账/结算等非核心任务可降级：延迟执行，不影响实时交易

### 3.3 数据一致性
- **NFR-008**：扣款操作必须保证"最多扣一次"（at-most-once），禁止重复扣款
- **NFR-009**：分账金额总和必须严格等于实付金额（误差为 0）
- **NFR-010**：退款后各账户余额必须准确回退，禁止资金悬空

### 3.4 安全
- **NFR-011**：所有资金操作必须双因素确认：系统校验 + 人工审核（大额）
- **NFR-012**：敏感接口（修改费率、强制退款）必须操作人身份验证 + 操作理由记录
- **NFR-013**：数据库资金字段使用 DECIMAL(18,4) 存储，禁止用浮点数
- **NFR-014**：资金操作接口限流：单账户 100 次/分钟，防止暴力重试

## 5. 数据模型

### 5.1 核心表结构

```sql
-- 结算单主表
CREATE TABLE settlement_order (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    settlement_id VARCHAR(64) NOT NULL UNIQUE COMMENT '结算单号',
    order_id VARCHAR(64) NOT NULL COMMENT '关联订单号',
    user_id VARCHAR(64) NOT NULL COMMENT '用户ID',
    merchant_id VARCHAR(64) NOT NULL COMMENT '商家ID',
    status VARCHAR(32) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/CHARGING/CHARGED/SPLITTING/SPLIT/REFUNDING/REFUNDED/CLOSED',
    total_amount DECIMAL(18,4) NOT NULL COMMENT '订单总金额',
    discount_amount DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '优惠金额',
    shipping_fee DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '运费',
    tax_amount DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '税费',
    platform_fee DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '平台服务费',
    payment_fee DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '支付手续费',
```

## 6. 状态机与流程

### 6.1 结算单状态机

```
[PENDING] 待扣款
    │ 订单完成事件触发
    ▼
[CHARGING] 扣款中 ──→ [CHARGED] 扣款成功 ──→ [SPLITTING] 分账中 ──→ [SPLIT] 已分账
    │                      │                      │                      │
    │ 扣款失败              │ 退款申请              │ 分账失败              │ 结算完成
    ▼                      ▼                      ▼                      ▼
[FAILED] 扣款失败    [REFUNDING] 退款中      [SPLIT_FAILED] 分账失败    [SETTLED] 已结算
    │ 可重试               │                      │ 人工处理              │
    ▼                      ▼                      ▼                      ▼
[CHARGING] 重试扣款  [REFUNDED] 已退款      [SPLIT] 重试分账      [CLOSED] 已关闭
```

### 6.2 正向流程（收款）

```
订单完成事件 → 生成账单明细 → 计算优惠分摊 → 校验风控规则
    → 创建结算单（PENDING）→ 调用支付渠道扣款 → 扣款成功更新 CHARGED
    → 执行分账规则 → 分账到各账户 → 更新 SPLIT → 日终生成结算批次 → 打款
```

### 6.3 逆向流程（退款）

```
退款申请 → 校验退款资格（是否已结算/已分账）→ 计算退款金额
    → 人工审核（大额）→ 审核通过 → 从各分账方账户扣回资金
    → 调用支付渠道退款 → 退款成功 → 更新退款单/结算单状态
```

## 7. 异常与边界场景

| 场景 | 预期行为 |
|------|---------|
| 扣款成功但系统宕机未更新状态 | 定时任务轮询支付渠道，根据渠道流水号回补状态 |
| 重复收到同一订单完成事件 | 基于订单号幂等，已生成结算单则忽略 |
| 分账时某分账方账户不存在 | 资金暂存到"待分账冻结账户"，触发告警通知运营开户 |
| 退款时原支付渠道已关闭 | 退到用户余额账户，通知用户提现 |
| 汇率变动导致跨境订单金额差异 | 以扣款时的汇率为准，差异由平台承担 |
| 对账发现渠道多了一笔我方没有的流水 | 标记为"渠道单边账"，人工核实后补单或调账 |
| 结算打款时银行卡已注销 | 打款失败，通知商家更新银行卡，资金保留在账户余额 |
| 用户同时发起退款和提现 | 优先处理退款（冻结对应金额），提现排队等待 |

## 8. 附录

### 8.1 错误码定义

| 错误码 | 描述 | 处理建议 |
|--------|------|---------|
| FIN-001 | 结算单已存在 | 幂等处理，直接返回已有结算单 |
| FIN-002 | 扣款幂等重复 | 已扣款成功，禁止重复扣 |
| FIN-003 | 支付渠道余额不足 | 通知用户更换支付方式 |
| FIN-004 | 支付渠道风控拦截 | 引导用户联系银行/支付渠道 |
| FIN-005 | 分账比例校验失败 | 检查分账规则配置，比例之和必须=100% |
| FIN-006 | 退款金额超过可退金额 | 校验退款金额 ≤ 实付金额 - 已退金额 |
| FIN-007 | 账户余额不足（分账回退） | 记为欠款，从该账户后续收入中扣回 |
| FIN-008 | 对账差异超出阈值 | 人工介入核实，禁止自动平账 |
| FIN-009 | 风控规则拦截 | 进入人工审核流程 |
| FIN-010 | 发票开具失败 | 记录失败原因，支持手动重试 |
