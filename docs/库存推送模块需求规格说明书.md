# 库存推送模块需求规格说明书（PRD）

> 版本：v1.0  
> 编写日期：2026-08-03  
> 适用范围：上游库存系统与订单审单系统之间的数据集成层

---

## 1. 概述

### 1.1 背景
库存系统作为企业供应链的核心数据源，需向订单审单系统实时/准实时同步物料主数据及库存变动数据。本模块承担"数据集成网关"职责，负责接收、清洗、校验、转换上游库存数据，并以标准化格式向下游订单审单系统提供可靠的库存数据服务。

### 1.2 目标
- 实现库存数据从上游到下游的**可靠、幂等、可追溯**传输
- 屏蔽上游库存系统的数据结构差异，向下游提供**统一库存数据模型**
- 支持高并发批量推送，具备**削峰填谷**能力
- 建立完整的**对账与补偿机制**，确保数据最终一致性

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| SKU | 库存量单位，最小可售卖单元 |
| SPU | 标准化产品单元，聚合多个SKU |
| 可用库存 | 实际在库且未被锁定的可售库存 |
| 锁定库存 | 已被订单占用但尚未出库的库存 |
| 在途库存 | 已采购/调拨在运输途中，预计可入库数量 |
| 全量推送 | 一次性推送全部有效数据，通常用于初始化或日终同步 |
| 增量推送 | 仅推送发生变更的数据，通常用于实时同步 |
| ACK | 回执确认（Acknowledgement），下游成功接收后向上游返回确认 |

## 2. 功能需求

### 2.1 数据接收层

#### 2.1.1 多协议接收
- **FR-001**：支持 HTTP/HTTPS RESTful API 接收上游推送数据
- **FR-002**：支持消息队列（Kafka/RabbitMQ/Service Bus）消费模式接收
- **FR-003**：支持 SFTP/FTP 文件批量导入（用于历史数据迁移或全量同步）
- **FR-004**：接收接口需支持 JSON/XML 两种报文格式，可配置切换

#### 2.1.2 接收鉴权与安全
- **FR-005**：所有接收接口必须校验 API Key + 签名（HMAC-SHA256），防止伪造推送
- **FR-006**：支持 IP 白名单限制，非白名单 IP 直接拒绝连接
- **FR-007**：报文传输必须启用 TLS 1.2+ 加密
- **FR-008**：敏感字段（如成本价）需额外加密传输，使用 AES-256-GCM

#### 2.1.3 报文校验
- **FR-009**：必填字段缺失时立即拒绝，返回明确错误码（如 `MISSING_FIELD:warehouseId`）
- **FR-010**：字段格式校验：数值型字段不能传字符串，日期字段必须符合 ISO-8601
- **FR-011**：报文大小限制：单条报文不超过 2MB，批量报文不超过 50MB
- **FR-012**：支持报文压缩传输（gzip/deflate），接收端自动解压

### 2.2 数据清洗与转换层

#### 2.2.1 数据标准化
- **FR-013**：单位自动转换：上游按"箱"推送时，根据 SKU 配置自动换算为"件"
- **FR-014**：金额精度统一：所有金额字段统一转换为"分"（整数）存储，避免浮点误差
- **FR-015**：编码标准化：上游物料编码映射为企业统一 SKU 编码，支持多源编码映射表
- **FR-016**：时间标准化：所有时间戳统一转换为 UTC+8 标准格式存储

#### 2.2.2 数据清洗规则
- **FR-017**：空值处理：可配置为"忽略"、"填充默认值"或"拒绝"
- **FR-018**：异常值拦截：库存数量为负数时标记为异常数据，进入人工审核队列
- **FR-019**：重复数据去重：基于"物料ID+仓库ID+批次号+版本号"生成唯一指纹
- **FR-020**：数据截断/补齐：字符串超长自动截断（记录日志），短于最小长度自动补齐（可配置）

#### 2.2.3 版本兼容性
- **FR-021**：向前兼容：上游新增未知字段时，模块不崩溃，记录日志并忽略该字段
- **FR-022**：向后兼容：支持旧版本报文格式，通过报文头 `version` 字段路由到对应解析器
- **FR-023**：字段变更告警：检测到上游字段类型变更（如 string→int）时，触发告警通知运维

### 2.3 库存数据模型处理

#### 2.3.1 多维度库存管理
- **FR-024**：必须区分并存储以下库存维度：
  - 总库存（物理在库总量）
  - 可用库存（总库存 - 锁定库存 - 预留库存）
  - 锁定库存（已审单未发货占用）
  - 在途库存（采购在途/调拨在途）
  - 预留库存（活动预售/大客户预留）
  - 不良品库存（质检不合格）
- **FR-025**：各维度库存变动必须记录流水明细，支持追溯

#### 2.3.2 多仓/多货主隔离
- **FR-026**：支持按仓库维度隔离数据（北京仓、上海仓、海外仓）
- **FR-027**：支持按货主维度隔离数据（自营、供应商A、供应商B）
- **FR-028**：仓库+货主组合维度下，库存数据完全独立，禁止跨维度混用
- **FR-029**：支持虚拟仓逻辑：组合多个实体仓为一个虚拟仓对外提供库存视图

#### 2.3.3 效期与批次管理
- **FR-030**：库存推送必须包含：生产日期、有效期至、入库日期、批次号
- **FR-031**：支持先进先出（FIFO）/先到期先出（FEFO）策略配置
- **FR-032**：临期预警：有效期剩余 30% 时自动标记，推送预警事件
- **FR-033**：过期冻结：超过有效期自动冻结库存，从可用库存中扣除

### 2.4 数据分发层

#### 2.4.1 推送方式
- **FR-034**：支持主动推送（Push）：库存变动时实时推送到下游订单审单系统
- **FR-035**：支持被动查询（Pull）：下游通过 API 实时查询当前库存状态
- **FR-036**：支持事件订阅模式：下游订阅库存变动事件主题，自主消费

#### 2.4.2 推送策略
- **FR-037**：实时推送：可用库存变动 > 阈值（如 ±5）时立即触发推送
- **FR-038**：定时推送：每 5 分钟汇总变动数据批量推送（降低下游压力）
- **FR-039**：全量推送：每日凌晨 02:00 执行全量快照推送，用于日终对账
- **FR-040**：增量推送：仅推送发生变更的字段，减少网络传输量

#### 2.4.3 推送可靠性
- **FR-041**：推送失败自动重试：最多重试 3 次，间隔 1s → 5s → 15s（指数退避）
- **FR-042**：重试 3 次失败后，数据进入死信队列（DLQ），触发人工介入告警
- **FR-043**：推送必须等待下游 ACK 回执，超时时间 30s，无 ACK 视为失败
- **FR-044**：支持推送顺序保证：同一 SKU 的库存变动必须按时间顺序到达下游

### 2.5 幂等与去重机制

#### 2.5.1 幂等接收
- **FR-045**：基于"推送批次号 + 物料ID + 仓库ID + 版本号"生成幂等键
- **FR-046**：重复数据到达时，直接返回成功（不重复处理），记录重复接收日志
- **FR-047**：幂等键有效期 7 天，过期后允许重新处理（防止长期占用存储）

#### 2.5.2 幂等分发
- **FR-048**：向下游推送时携带唯一消息 ID（UUID），下游通过该 ID 去重
- **FR-049**：消息 ID 与上游推送批次号关联，支持端到端追溯

### 2.6 缓存与性能

#### 2.6.1 多级缓存
- **FR-050**：L1 缓存：本地 Caffeine 缓存热点 SKU 库存（命中率 > 80%）
- **FR-051**：L2 缓存：Redis 集群缓存全量库存摘要，TTL 5 分钟
- **FR-052**：缓存更新策略：写穿（Write-Through）+ 消息通知失效

#### 2.6.2 批量处理
- **FR-053**：支持批量接收：单次最多处理 5000 条库存记录
- **FR-054**：支持分页查询：下游分页查询库存，每页默认 100 条，最大 1000 条
- **FR-055**：流式处理：全量推送时采用流式读取，避免一次性加载到内存

### 2.7 对账与监控

#### 2.7.1 日终对账
- **FR-056**：每日 03:00 自动执行对账任务：
  - 上游推送日志统计：昨日共推送多少条、成功多少条、失败多少条
  - 下游接收日志统计：昨日共接收多少条、处理成功多少条
  - 差异告警：上下游数量差异 > 0 时触发告警
- **FR-057**：对账差异处理：自动生成差异报告，支持人工标记"已处理"或"重新推送"

#### 2.7.2 实时监控
- **FR-058**：推送成功率监控：低于 99.9% 触发告警
- **FR-059**：推送延迟监控：P99 延迟 > 3s 触发告警
- **FR-060**：积压监控：待处理队列积压 > 10000 条触发告警
- **FR-061**：数据质量监控：脏数据比例 > 1% 触发告警

## 3. 非功能需求

### 3.1 性能
- **NFR-001**：单条库存推送处理延迟 < 100ms（P99）
- **NFR-002**：批量推送（5000 条）处理时间 < 30s
- **NFR-003**：库存查询 API QPS 支持 > 5000
- **NFR-004**：系统支持水平扩展，通过增加实例数线性提升吞吐量

### 3.2 可用性
- **NFR-005**：系统可用性 SLA > 99.95%（全年停机 < 4.38 小时）
- **NFR-006**：故障自动切换：数据库/Redis 主从故障时，30s 内自动切换
- **NFR-007**： graceful degradation：下游不可用时，缓存数据可继续提供读服务（允许 5 分钟延迟）

### 3.3 数据一致性
- **NFR-008**：库存数据最终一致性：上下游数据差异在 5 分钟内收敛
- **NFR-009**：强一致性场景：锁库存/解锁库存操作必须强一致，使用分布式锁

### 3.4 安全
- **NFR-010**：所有数据访问必须记录审计日志（谁、什么时候、查了什么）
- **NFR-011**：数据库敏感字段（成本价）加密存储
- **NFR-012**：接口防刷：单 IP 限流 1000 次/分钟

## 5. 数据模型

### 5.1 核心表结构

```sql
-- 库存主表
CREATE TABLE inventory_sku (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sku_id VARCHAR(64) NOT NULL COMMENT '标准化SKU编码',
    warehouse_id VARCHAR(64) NOT NULL COMMENT '仓库编码',
    owner_id VARCHAR(64) NOT NULL COMMENT '货主编码',
    total_qty INT NOT NULL DEFAULT 0 COMMENT '总库存',
    available_qty INT NOT NULL DEFAULT 0 COMMENT '可用库存',
    locked_qty INT NOT NULL DEFAULT 0 COMMENT '锁定库存',
    in_transit_qty INT NOT NULL DEFAULT 0 COMMENT '在途库存',
    reserved_qty INT NOT NULL DEFAULT 0 COMMENT '预留库存',
    version INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_sku_warehouse_owner (sku_id, warehouse_id, owner_id)
);

-- 库存流水表
CREATE TABLE inventory_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sku_id VARCHAR(64) NOT NULL,
    warehouse_id VARCHAR(64) NOT NULL,
    owner_id VARCHAR(64) NOT NULL,
    change_type VARCHAR(32) NOT NULL COMMENT '变动类型：PUSH/LOCK/UNLOCK/RESERVE',
    delta_qty INT NOT NULL COMMENT '变动数量（可正可负）',
    before_qty INT NOT NULL,
    after_qty INT NOT NULL,
    batch_id VARCHAR(128) COMMENT '关联批次号',
    source_batch_id VARCHAR(128) COMMENT '上游推送批次号',
    message_id VARCHAR(64) COMMENT '下游分发消息ID',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_sku_time (sku_id, created_at),
    INDEX idx_batch (source_batch_id)
);

-- 批次库存表
CREATE TABLE inventory_batch (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sku_id VARCHAR(64) NOT NULL,
    warehouse_id VARCHAR(64) NOT NULL,
    batch_no VARCHAR(64) NOT NULL,
    production_date DATE,
    expiry_date DATE,
    qty INT NOT NULL DEFAULT 0,
    status VARCHAR(16) DEFAULT 'VALID' COMMENT 'VALID/EXPIRED/FROZEN',
    UNIQUE KEY uk_sku_warehouse_batch (sku_id, warehouse_id, batch_no)
);

-- 幂等控制表
CREATE TABLE idempotent_record (
    idempotency_key VARCHAR(128) PRIMARY KEY COMMENT '幂等键：batchId_skuId_warehouseId_version',
    batch_id VARCHAR(128) NOT NULL,
    status VARCHAR(16) DEFAULT 'SUCCESS' COMMENT 'SUCCESS/FAILED',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expire_at TIMESTAMP NOT NULL COMMENT '过期时间',
    INDEX idx_expire (expire_at)
);
```

## 6. 状态机与流程

### 6.1 库存推送处理流程

```
[上游推送] → [鉴权校验] → [报文解析] → [幂等检查] → [数据清洗]
    → [数据转换] → [库存更新] → [流水记录] → [缓存刷新] → [下游分发]
    → [ACK回执]
```

### 6.2 异常处理分支

```
鉴权失败 → 直接拒绝，返回 401
报文格式错误 → 记录错误日志，返回 400，不入库
幂等重复 → 返回 200（已处理），记录重复日志
数据清洗失败 → 进入脏数据队列，人工处理，返回 202（已接收待处理）
库存更新冲突 → 乐观锁重试 3 次，失败进入重试队列
下游分发失败 → 进入重试队列，按策略重试，最终进 DLQ
```

## 7. 异常与边界场景

| 场景 | 预期行为 |
|------|---------|
| 上游推送了不存在的 SKU | 记录到"待映射SKU队列"，触发人工映射流程，不阻塞其他数据 |
| 同一秒收到同一 SKU 的多次推送 | 按版本号排序处理，版本号大的覆盖小的，版本号相同按时间戳 |
| 可用库存被扣为负数 | 拦截并告警，标记为异常数据，不更新到主表 |
| 下游系统长时间不可用 | 数据堆积在消息队列，队列满时触发流控，拒绝新的上游推送 |
| 数据库主从切换 | 自动重连，正在处理的事务回滚后由上游重试补偿 |
| 缓存与数据库不一致 | 定时任务每 5 分钟比对缓存与数据库，差异 > 0 时刷新缓存并告警 |

## 8. 附录

### 8.1 错误码定义

| 错误码 | 描述 | 处理建议 |
|--------|------|---------|
| INV-001 | 鉴权失败 | 检查 API Key 和签名 |
| INV-002 | 报文格式错误 | 检查 JSON 格式和字段类型 |
| INV-003 | 必填字段缺失 | 补充缺失字段后重推 |
| INV-004 | 幂等重复 | 无需处理，已生效 |
| INV-005 | SKU 映射失败 | 人工维护 SKU 映射表 |
| INV-006 | 库存更新冲突 | 系统自动重试，持续失败则人工介入 |
| INV-007 | 下游分发失败 | 检查下游服务状态，数据已进入重试队列 |
| INV-008 | 数据超时 | 推送处理超过 30s，建议拆分批量大小 |
