# 开发规范与工程约定

> **文档定位**：全项目的编码规范、分层规则、命名约定、Git 工作流、测试规范。
> **适用范围**：所有模块、所有开发者

## 一、DDD 分层规范

### 1.1 四层职责

| 层 | 包路径 | 职责 | 依赖规则 |
|----|--------|------|----------|
| **domain** | `*.domain` | 纯业务规则：聚合根、实体、值对象、领域服务、领域事件、Repository 接口 | **零框架依赖**（无 Spring/MyBatis/JPA） |
| **application** | `*.application` | 用例编排：事务边界、DTO 转换、事件发布、调用领域服务 | 依赖 domain |
| **infrastructure** | `*.infrastructure` | 技术实现：Repository 实现、Feign 客户端、Kafka 生产者、配置类 | 依赖 domain（实现接口）+ application |
| **interfaces/api** | `*.interfaces` | 对外接口：Controller、请求/响应 DTO、参数校验 | 依赖 application + infrastructure |

### 1.2 依赖方向（严格单向）

```
interfaces → application → domain ← infrastructure
```

**禁止的依赖**：
- domain 依赖任何框架（Spring/MyBatis/JPA/Jackson）
- application 直接操作数据库（必须通过 Repository 接口）
- infrastructure 直接被 Controller 调用（必须经过 Application 层）
- 跨层循环依赖

### 1.3 各层代码规范

#### Domain 层

```java
// 聚合根：行为内聚，不暴露 setter
public class Order extends BaseEntity {
    private OrderId id;
    private OrderNo orderNo;
    private OrderStatus status;
    private List<OrderItem> items;
    private Money totalAmount;

    // 工厂方法（不在构造器中写业务逻辑）
    public static Order create(OrderCreateSpec spec) {
        Order order = new Order();
        order.id = spec.getOrderId();
        order.orderNo = spec.getOrderNo();
        order.status = OrderStatus.TO_BE_CONFIRMED;
        order.items = spec.getItems();
        order.recalculateAmount();
        return order;
    }

    // 状态迁移（行为方法，不是 setter）
    public void confirm() {
        if (!status.canTransitTo(OrderStatus.CONFIRMED)) {
            throw new BizException("800102", "当前状态不允许确认");
        }
        this.status = OrderStatus.CONFIRMED;
    }

    // 不暴露 setter
    // 不依赖任何框架
    // 不直接操作数据库
}
```

```java
// 状态机枚举：迁移表内聚
public enum OrderStatus {
    TO_BE_CONFIRMED,
    CONFIRMED,
    TRANSFERRING,
    TRANSFERRED,
    SHIPPING,
    SHIPPED,
    SIGNED,
    CLOSED,
    CANCELLED,
    REJECTED;

    private static final EnumMap<OrderStatus, Set<OrderStatus>> TRANSITIONS;

    static {
        TRANSITIONS = new EnumMap<>(OrderStatus.class);
        TRANSITIONS.put(TO_BE_CONFIRMED, Set.of(CONFIRMED, REJECTED, CANCELLED));
        TRANSITIONS.put(CONFIRMED, Set.of(TRANSFERRING, CANCELLED));
        TRANSITIONS.put(TRANSFERRING, Set.of(TRANSFERRED));
        TRANSITIONS.put(TRANSFERRED, Set.of(SHIPPING));
        TRANSITIONS.put(SHIPPING, Set.of(SHIPPED));
        TRANSITIONS.put(SHIPPED, Set.of(SIGNED));
        TRANSITIONS.put(SIGNED, Set.of(CLOSED));
    }

    public boolean canTransitTo(OrderStatus target) {
        return TRANSITIONS.getOrDefault(this, Set.of()).contains(target);
    }
}
```

#### Application 层

```java
@Service
@Transactional
public class OrderApplicationService {

    private final OrderRepository orderRepository;
    private final OrderEventPublisher eventPublisher;

    // 构造器注入（不用 @Autowired 字段注入）
    public OrderApplicationService(OrderRepository orderRepository,
                                   OrderEventPublisher eventPublisher) {
        this.orderRepository = orderRepository;
        this.eventPublisher = eventPublisher;
    }

    public OrderResult createOrder(OrderCreateCommand command) {
        // 1. 领域逻辑（调用聚合根工厂方法）
        Order order = Order.create(command.toSpec());

        // 2. 持久化
        orderRepository.save(order);

        // 3. 发布事件
        eventPublisher.publish(OrderCreatedEvent.of(order));

        // 4. 返回结果
        return OrderResult.from(order);
    }
}
```

#### Infrastructure 层

```java
@Repository
public class OrderRepositoryImpl implements OrderRepository {

    private final OrderMapper orderMapper;
    private final OrderSkuMapper orderSkuMapper;

    @Override
    public Order findById(OrderId id) {
        OrderPO po = orderMapper.selectById(id.getValue());
        if (po == null) return null;
        List<OrderSkuPO> skuPOs = orderSkuMapper.findByOrderId(id.getValue());
        return OrderAssembler.toDomain(po, skuPOs);
    }

    @Override
    public void save(Order order) {
        OrderPO po = OrderAssembler.toPO(order);
        orderMapper.insertOrUpdate(po);
        // 明细：全删全插（简化策略）
        orderSkuMapper.deleteByOrderId(order.getId().getValue());
        order.getItems().forEach(item -> {
            OrderSkuPO skuPO = OrderAssembler.toSkuPO(item, order.getId());
            orderSkuMapper.insert(skuPO);
        });
    }
}
```

#### Interfaces 层

```java
@RestController
@RequestMapping("/api/orders")

    private final OrderApplicationService orderAppService;
```

## 三、Git 工作流

### 3.1 分支模型

```
main          生产分支（保护分支，只通过 PR 合入）
  ├── develop   开发主分支
  │     ├── feature/xxx   功能分支
  │     ├── fix/xxx       修复分支
  │     └── refactor/xxx  重构分支
  └── hotfix/xxx  紧急修复（从 main 拉出，修完合回 main 和 develop）
```

### 3.2 分支命名

```
feature/{需求编号}-{简述}    如：feature/F-301-create-order
fix/{问题简述}              如：fix/credit-concurrent-issue
refactor/{重构内容}         如：refactor/merge-common-module
hotfix/{问题简述}           如：hotfix/order-status-bug
```

### 3.3 Commit 规范

```
格式：{type}({scope}): {description}

type：
  feat     新功能
  fix      修复 bug
  refactor 重构（不改功能）
  docs     文档
  test     测试
  chore    构建/配置/依赖

scope：模块名（order/customer/inventory/billing/fulfillment/auth/common）

示例：
  feat(order): 实现拆单逻辑
  fix(customer): 修复信用并发超卖问题
  refactor(common): 合并三个 common 模块
  docs(architecture): 更新架构设计文档
  test(order): 补充状态机边界测试用例
```

### 3.4 PR 规范

- PR 标题同 commit 规范
- PR 描述包含：改了什么、为什么改、影响范围、测试方式
- 至少 1 人 Review 通过
- CI 全绿（编译 + 测试 + 静态扫描）
- 不允许 force push 到 develop/main

## 四、测试规范

### 4.1 测试分层

| 层级 | 测试类型 | 覆盖目标 | 工具 |
|------|----------|----------|------|
| Domain | 单元测试 | 状态机/金额计算/校验规则 | JUnit 5 + Mockito |
| Application | 单元测试 | 用例编排（Mock 依赖） | JUnit 5 + Mockito |
| Infrastructure | 集成测试 | Repository/Feign/Kafka | Spring Boot Test + Testcontainers |
| Interfaces | 集成测试 | Controller API | MockMvc / WebTestClient |
| E2E | 端到端测试 | 下单→审单→发货→结算全链路 | Spring Boot Test |

### 4.2 测试命名

```java
// 格式：方法名_条件_预期结果
@Test
void confirm_whenStatusIsToBeConfirmed_shouldTransitToConfirmed() { ... }

@Test
void confirm_whenStatusIsShipped_shouldThrowBizException() { ... }

@Test
void createOrder_whenCreditInsufficient_shouldThrowCreditException() { ... }
```

### 4.3 测试覆盖目标

| 模块 | 覆盖率目标 | 重点 |
|------|-----------|------|
| domain | ≥ 80% | 状态机迁移、金额计算、校验规则 |
| application | ≥ 60% | 用例编排、异常分支 |
| infrastructure | ≥ 40% | Repository CRUD、Feign 调用 |
| interfaces | ≥ 30% | API 参数校验、权限校验 |

### 4.4 测试数据

- 单元测试：使用 Builder 或工厂方法构造测试数据，不用 `@SpringBootTest`
- 集成测试：使用 Testcontainers 启动 MySQL/Kafka
- 不依赖共享的测试数据文件，每个测试自包含

## 五、代码质量门禁

### 5.1 编译门禁

- `mvn clean compile` 全模块编译通过
- 无 unchecked warning
- 无 deprecated API 使用（除非有 TODO 注明迁移计划）

### 5.2 测试门禁

- `mvn test` 全部通过
- 核心领域层测试覆盖率 ≥ 80%
- 无跳过的测试（`@Disabled` 需注明原因和修复计划）

### 5.3 静态扫描门禁

- 无 Blocker / Critical 级别问题（SonarQube）
- 无循环依赖（ArchUnit 架构测试）
- domain 层零框架依赖（ArchUnit 守护）

## 六、异常处理规范

### 6.1 异常分类

| 类型 | 基类 | 处理方式 | 示例 |
|------|------|----------|------|
| 业务异常 | `BizException` | 全局捕获，转 ApiResponse | 信用不足、库存不足、状态非法 |
| 参数校验异常 | `MethodArgumentNotValidException` | 全局捕获，转 400 | 字段为空、格式错误 |
| 权限异常 | `AccessDeniedException` | 全局捕获，转 403 | 无权限、未登录 |
| 系统异常 | `RuntimeException` | 全局捕获，转 500 | NPE、DB 异常 |

### 6.2 异常处理原则

- **业务异常用 BizException**：携带错误码 + 用户可读消息
- **不在 domain 层 try-catch**：异常向上抛，由 application 层处理
- **不吞异常**：catch 后必须处理（记录日志或重新抛出）
- **Feign 异常转译**：Feign 调用失败时，转换为本地 BizException

### 6.3 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BizException.class)
    public ApiResponse<Void> handleBizException(BizException e) {
        return ApiResponse.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(f -> f.getField() + ": " + f.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return ApiResponse.fail("400", msg);
    }

    @ExceptionHandler(AccessDeniedException.class)
    public ApiResponse<Void> handleAccessDenied(AccessDeniedException e) {
        return ApiResponse.fail("403", "无权限执行该操作");
    }

    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleSystem(Exception e) {
        log.error("系统异常", e);
        return ApiResponse.fail("500", "系统内部错误");
    }
}
```

## 七、金额处理规范

- **使用 BigDecimal**，禁止使用 double/float
- **精度 4 位小数**（DECIMAL(18,4)）
- **比较用 compareTo**，不用 equals（`new BigDecimal("1.0")` 不等于 `new BigDecimal("1.00")`）
- **运算指定 RoundingMode**：`amount.divide(divisor, 4, RoundingMode.HALF_UP)`
- **金额分摊**：最后一行用总额减去前面各行之和（避免分摊后合计不等于总额）

```java
// 正确的分摊方式
BigDecimal totalDiscount = order.getDiscountAmount();
BigDecimal allocated = BigDecimal.ZERO;
for (int i = 0; i < items.size() - 1; i++) {
    BigDecimal ratio = items.get(i).getAmount()
        .divide(totalAmount, 4, RoundingMode.HALF_UP);
    BigDecimal itemDiscount = totalDiscount.multiply(ratio)
        .setScale(4, RoundingMode.HALF_UP);
    items.get(i).setDiscountAmount(itemDiscount);
    allocated = allocated.add(itemDiscount);
}
// 最后一行 = 总折扣 - 已分摊
items.get(items.size() - 1)
    .setDiscountAmount(totalDiscount.subtract(allocated));
```
