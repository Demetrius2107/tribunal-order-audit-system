# 数据库设计文档

> **文档定位**：定义目标架构下所有系统的数据库表结构、索引策略、ER 关系。
> **前置文档**：《目标系统架构设计文档》
> **设计原则**：每系统独立数据库、数据所有权唯一、金额用 DECIMAL(18,4)、主键用雪花 ID

---

## 二、tribunal_oms（订单中台）

### 2.1 订单主表 t_order

```sql
CREATE TABLE t_order (
    id                      VARCHAR(64)   NOT NULL COMMENT '主键（雪花ID）',
    order_no                VARCHAR(64)   NOT NULL COMMENT '订单编号（业务唯一键）',
    customer_id             VARCHAR(64)   NOT NULL COMMENT '客户ID',
    customer_code           VARCHAR(64)   NOT NULL COMMENT '客户编码（冗余，减少跨域查询）',
    order_type              VARCHAR(32)   NOT NULL DEFAULT 'NORMAL' COMMENT '订单类型：NORMAL/PRE_ORDER',
    status                  VARCHAR(32)   NOT NULL COMMENT '状态机：TO_BE_CONFIRMED/CONFIRMED/TRANSFERRING/TRANSFERRED/SHIPPING/SHIPPED/SIGNED/CLOSED/CANCELLED/REJECTED',
    channel                 VARCHAR(32)   NOT NULL DEFAULT 'API' COMMENT '来源渠道：API/PORTAL/POS/EDI',
    warehouse_id            VARCHAR(64)   NULL COMMENT '寻源分仓结果（目标仓库）',

    -- 金额
    total_amount            DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '商品总金额',
    discount_amount         DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '促销折扣金额',
    discount_pool_deduction DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '折扣池抵扣',
    deposit_amount          DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '押金',
    tax_amount              DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '税费',
    shipping_fee            DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '运费',
    payable_amount          DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '应付金额',

    -- 拆单关系
    parent_order_id         VARCHAR(64)   NULL COMMENT '父订单ID（拆单后的子订单指向父订单）',
    is_split                TINYINT       NOT NULL DEFAULT 0 COMMENT '是否已拆单 0否1是',

    -- 拼车
    car_pooling             TINYINT       NOT NULL DEFAULT 0 COMMENT '是否拼车 0否1是',
    car_pool_joined         TINYINT       NOT NULL DEFAULT 0 COMMENT '是否已拼车 0否1是',

    -- 审单
    reject_reason           VARCHAR(512)  NULL COMMENT '拒绝原因',
    reviewer                VARCHAR(64)   NULL COMMENT '审单人',
    reviewed_at             DATETIME      NULL COMMENT '审单时间',

    -- 本地消息表（Transactional Outbox）
    outbox_status           VARCHAR(16)   NOT NULL DEFAULT 'PENDING' COMMENT '消息表状态：PENDING/SENT',
    outbox_retry_count      INT           NOT NULL DEFAULT 0 COMMENT '消息表重试次数',

    -- 通用字段
    version                 BIGINT        NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
    create_time             DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time             DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted                 TINYINT       NOT NULL DEFAULT 0 COMMENT '逻辑删除',

    PRIMARY KEY (id),
    UNIQUE KEY uk_order_no (order_no),
    KEY idx_customer (customer_id, status),
    KEY idx_status (status),
    KEY idx_parent (parent_order_id),
    KEY idx_create_time (create_time)
) ENGINE = InnoDB COMMENT = '订单主表';
```

## 八、索引策略

| 表 | 索引 | 类型 | 用途 |
|----|------|------|------|
| t_order | uk_order_no | UNIQUE | 幂等兜底 |
| t_order | idx_customer_status | NORMAL | 客户维度查单 |
| t_order | idx_create_time | NORMAL | 时间范围查单 |
| t_order | idx_parent | NORMAL | 拆单关系查询 |
| t_order_sku | idx_order | NORMAL | 按订单查明细 |
| t_order_sku | idx_sku | NORMAL | 按 SKU 查销量 |
| t_customer | uk_customer_code | UNIQUE | 幂等兜底 |
| t_credit_flow | idx_customer_time | NORMAL | 信用流水查询 |
| inventory_sku | uk_sku_warehouse_owner | UNIQUE | 多维库存唯一键 |
| inventory_log | idx_sku_time | NORMAL | 库存追溯 |
| settlement_order | uk_settlement | UNIQUE | 结算单幂等 |
| payment_idempotent | PRIMARY (idempotency_key) | PK | 扣款幂等 |

### 索引设计原则

1. **唯一索引 = 幂等兜底**：order_no、customer_code、settlement_id、source_order_no 等业务唯一键必须有唯一约束
2. **查询索引 = 最左前缀**：复合索引按等值条件→范围条件→排序字段排列
3. **避免冗余索引**：单表索引不超过 5 个
4. **大表考虑覆盖索引**：列表查询场景设计覆盖索引避免回表

## 九、分库分表规划

### 何时分片

| 表 | 预估单表行数/年 | 分片阈值 | 分片策略 |
|----|----------------|----------|----------|
| t_order | 500 万+ | 2000 万 | 按客户 ID 哈希分 16 库 |
| t_order_sku | 2000 万+ | 5000 万 | 跟随订单分片 |
| t_order_status_record | 2000 万+ | 5000 万 | 跟随订单分片 |
| inventory_log | 1000 万+ | 3000 万 | 按时间月分表 |
| account_transaction | 500 万+ | 2000 万 | 按账户 ID 哈希 |

### 分片工具

ShardingSphere-JDBC（无需额外中间件，应用层分片）

### 不分片的表

- t_customer：客户数量有限（通常 < 10 万），不分片
- 配置类表（t_price_rule / t_promotion_rule / t_deposit_rule）：数据量小
- t_outbox_message：发送后可定期清理，保持小表
