# 架构总览（完整业务骨架）

> **项目**：tribunal-order-audit-system — B2B 订单审单系统（DDD + 微服务形态）
> **定位**：上游（物料+金额）→ 中游（订单审单）→ 下游（金融+履约）的完整业务闭环，全部模块合于同一项目
> **形态**：15 个模块（3 共享内核 + 9 业务模块 + 2 独立系统 + 网关），逻辑域独立（模块化微服务）、部署合一（同一工程）
> **技术栈**：Spring Boot 3.2.x / Spring Cloud OpenFeign / MyBatis-Plus / MySQL（每模块独立库）/ JDK 21

---

## 一、模块全景（15 模块）

```
tribunal-order-audit-system
│
├── 共享内核（R1 合并产物，非微服务）
│   ├── tribunal-common-core/            # 核心层：ApiResponse / BizException / 跨服务 DTO
│   ├── tribunal-common-starter/         # 起步依赖：JWT 鉴权 / MyBatis-Plus / Feign 自动装配
│   └── tribunal-common-event/           # 事件契约层：跨系统领域事件（Kafka 消息体）
│
├── 上游（前置：物料 + 金额）
│   ├── tribunal-order-inventory-service/     # 库存物料域：主数据/库存账/预占释放
│   └── tribunal-order-marketing-service/     # 营销价格域：价格体系/促销/折扣/押金引擎
│
├── 中游（核心交易）
│   ├── tribunal-order-auth-service/          # 认证授权域：用户/角色/登录/RBAC
│   ├── tribunal-order-customer-service/      # 客户信用域：客户/信用组/信用额度
│   └── tribunal-order-service/               # 订单审单域：下单/状态机/审单/五合一编排
│
├── 下游（后置：金融 + 履约）
│   ├── tribunal-order-billing-service/       # 金融账单域：账单生成/审核/结算/核销/回传
│   └── tribunal-order-fulfillment-service/   # 履约执行域：出库/发货/签收/发送工厂
│
├── 横贯（支撑能力）
│   ├── tribunal-order-notification-service/  # 通知域：站内信/邮件/短信/微信
│   └── tribunal-order-task-service/          # 定时任务域：超时关单/状态对账/数据归档
│
├── 独立系统（共享同一 common 内核）
│   ├── tribunal-inventory-push-service/      # 库存推送系统：主数据/库存推送上游
│   └── tribunal-finance-settlement-service/  # 金融结算系统：账单结算/核销/资金流
│
└── 网关
    └── tribunal-gateway/                     # M5：统一入口/路由/Nacos 服务发现/JWT 前置鉴权
```

## 三、业务三大块闭环

```
【上游】拿物料 + 金额
  inventory（物料/库存/预占）───┬─── marketing（价格/促销/押金）
                                │
【中游】订单审单                 ▼
  auth（登录鉴权）→ customer（信用）→ order（下单/审单/状态机）
                                │
【下游】金融处理 + 履约 + 发工厂  ▼
  billing（账单/结算/核销）→ fulfillment（出库/发货/签收/发送工厂）
                                │
【横贯】                        ▼
  notification（通知）＋ task（超时关单/对账/归档）
```

## 四、order-service 五合一编排链路（核心）

```
审单通过(order-service)
  ① 信用校验      → customer-service（可用信用 ≥ 应付）
  ② 取价校验      → marketing-service（客户价→客户组价→区域价，上游"金额"）
  ③ 预占库存      → inventory-service（逐 SKU 预占，防超卖）
  ④ 生成账单      → billing-service（账单 GENERATED，转单）
  ⑤ 创建履约      → fulfillment-service（履约 GENERATED，待出库/发货）
  ⑥ 发送通知      → notification-service（站内信给经销商）
  ⑦ 状态迁移      → order 状态机：待确认 → 已确认
```

**账单/履约回传**：
- billing 结算/核销 → 回传 order → 订单状态机推进（转单中 → 已转单）
- fulfillment 发货/签收 → 回传 order → 订单终态（已发货/已签收）

## 六、本地启动与联调

```bash
# 1. 建库建表（13 份 SQL 按序执行）
mysql -uroot -p < docs/sql/auth.sql
mysql -uroot -p < docs/sql/customer.sql
mysql -uroot -p < docs/sql/order.sql
mysql -uroot -p < docs/sql/inventory.sql
mysql -uroot -p < docs/sql/marketing.sql
mysql -uroot -p < docs/sql/billing.sql
mysql -uroot -p < docs/sql/fulfillment.sql
mysql -uroot -p < docs/sql/notification.sql
mysql -uroot -p < docs/sql/task.sql

# 2. 修改各服务 application.yml 数据库账号密码

# 3. 启动顺序（依赖下游先行）
mvn -pl tribunal-order-auth-service spring-boot:run          # 8087
mvn -pl tribunal-order-customer-service spring-boot:run      # 8081
mvn -pl tribunal-order-inventory-service spring-boot:run     # 8083
mvn -pl tribunal-order-marketing-service spring-boot:run     # 8084
mvn -pl tribunal-order-billing-service spring-boot:run       # 8082
mvn -pl tribunal-order-fulfillment-service spring-boot:run   # 8085
mvn -pl tribunal-order-notification-service spring-boot:run  # 8086
mvn -pl tribunal-order-task-service spring-boot:run          # 8088
mvn -pl tribunal-order-service spring-boot:run               # 8080（最后，编排中心）

# 4. 联调验证（建议用例）
# ① 登录取 Token：POST /api/auth/login
# ② 物料入库：POST /api/inventory/items
# ③ 价格配置：POST /api/marketing/price
# ④ 下单：POST /api/orders（状态=待确认）
# ⑤ 审单：POST /api/orders/{id}/review（触发五合一编排）
# ⑥ 账单结算：POST /api/bills/{id}/settle（回传订单状态机）
# ⑦ 履约发货/签收：POST /api/fulfillments/{id}/ship、/sign
# ⑧ 查通知：GET /api/notifications/{id}
```
